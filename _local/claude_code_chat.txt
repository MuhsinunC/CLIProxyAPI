  I investigated the issue and found the root cause. Here's what I discovered:  
                                                                                
  The Problem                                                                   
                                                                                
  When using gemini-claude-opus-4-5(high) or similar thinking budget suffixes,  
  the thinking budget was not being applied because:                            
                                                                                
  1. Missing model config: The gemini-claude-opus-4-5 and                       
  gemini-claude-sonnet-4-5 (non-thinking variants) were not defined in          
  GetAntigravityModelConfig(). Only the -thinking suffixed variants had thinking
   support.                                                                     
  2. Missing alias mapping: There was no mapping for claude-opus-4-5 →          
  gemini-claude-opus-4-5 in modelName2Alias().                                  
  3. How it fails: When util.ModelSupportsThinking("gemini-claude-opus-4-5") was
   called, it returned false because the model wasn't in the registry with      
  thinking support, causing the thinking budget to be ignored.                  
                                                                                
  The Fix                                                                       
                                                                                
  I made the following changes:                                                 
                                                                                
  1. internal/registry/model_definitions.go: Added thinking support for:        
    - gemini-claude-sonnet-4-5                                                  
    - gemini-claude-opus-4-5                                                    
  2. internal/runtime/executor/antigravity_executor.go: Added alias mappings:   
    - claude-opus-4-5 → gemini-claude-opus-4-5 (in modelName2Alias)             
    - gemini-claude-opus-4-5 → claude-opus-4-5 (in alias2ModelName)             
                                                                                
  For Claude Provider                                                           
                                                                                
  The Claude provider (direct Anthropic API) models like                        
  claude-opus-4-5-20251101(high) should work correctly because they have        
  ThinkingSupport defined in GetClaudeModels(). If you're experiencing issues   
  with Claude provider models, it might be a different issue - could you provide
   more details about what's not working?
